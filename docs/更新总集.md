### 本次约定要记住的三件事

1. 总集不能只写“修了 bug”，要写清症状、根因、改法，方便以后回溯。
2. 坑要写成“现象 → 原因 → 做法”，不要只写结论。
3. 改完同步：APK、源码包、`texts-defaults.json`、`texts.json`、四份文档，一个都不能漏。

## 云控配置验签 + 防重放（0.5.3 → 0.5.4，2026-11-06）

- **改了什么**
  - `module/src/main/java/xwdy/deepseek/test/Cloud.java` 重写：拉取 cloud.json 后先验签再使用；`fetch()` 增加 `Context` 参数；新增 `canonical()`（被签字段的固定顺序拼接串）、`verify()`；失败只写一行日志，仍保持「失败静默、不阻断本地功能」。
  - 新增 `tools/CloudSign.java`（keygen / sign / verify，自带极简 JSON 解析，不依赖 org.json）+ `tools/sign-cloud.sh`（自动 seq +1、签名、可选 `--upload` PUT 到服务器）。
  - `MainActivity.loadCloud()` 改为 `Cloud.fetch(MainActivity.this, …)`。
  - 服务器 `cloud.json` 增加 `seq` 与 `sig` 两个字段，当前 `seq=6`、`minVersionCode=221`、`blockedVersionCodes=[]`。
- **为什么**：云控走 HTTP 明文（服务器只有 AAAA、8081 无 TLS），中间人可改 `notice` / `minVersionCode` / `blockedVersionCodes` / `downloadUrl`。上 TLS 需要另签证书并改 nginx（本次不做），先用签名挡住伪造。
- **签名设计**：ECDSA P-256（`SHA256withECDSA`），签的是 `MCTGA-CLOUD-1\nseq=…\nminVersionCode=…\nblocked=升序逗号\nnotice=…\ndownloadUrl=…\n` 的 UTF-8 字节；JSON 排版、键序、多余字段都不参与签名。公钥写死在 `Cloud.PUBKEY_B64`，私钥只在本机 `/data/local/tmp/ws/keys/cloud.key`（不进仓库、不进源码包，备份见交接说明）。
- **防重放**：`seq` 单调递增，App 把见过的最大 seq 存在 `cfg` 偏好 `cloud_seq`，比它小的合法配置会被忽略。回滚配置也要 +1，不能把 seq 改小。
- **版本**：`0.5.3` / 223 是内部冒烟包（只装本机、未发布）；`0.5.4` / 224 为正式产物。
- **影响面**：只影响云控（公告 / 强制更新 / 停用版本）。0.5.4 起若配置签名不对，等同没拉到配置（静默）；≤0.5.3 的客户端不验签、行为不变，所以现在服务器上的带 `sig` 配置对老版本照样生效。
- **旧版编辑器注意**：`xwdy.deepseek.cloud`（cloud-editor）直接 PUT 会抹掉 `sig`，之后新客户端会忽略这份配置——用它改完必须在本机跑 `sh tools/sign-cloud.sh --upload` 重签。

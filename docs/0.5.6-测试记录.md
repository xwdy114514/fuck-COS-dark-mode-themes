# MCTGA 0.5.6 / 226 无主题背景残留修复验证

## 问题与修复

用户明确确认手机处于未应用第三方主题状态。/data/theme 根目录仅 config/applying，配置的应用资源路径为空，但旧补齐目录仍有资源；旧 Hook 会因此继续显示背景。此前 0.5.5 的“看到插画”只是观察，不是默认主题场景的正确结果。

新增 AppliedTheme 只读证据门槛：根目录真实、非空且可打开的 com.* 应用主题 ZIP 才能激活主题注入。不递归 applying、不把 config、下载文件、补齐缓存、图标、壁纸或残留 UUID 当成已应用主题。未知状态保守不注入。入口、资源回调、视图操作及延迟任务均受门槛约束。

## 范围与限制

- 本轮真机验证为 PJD110/Android 17 的当前无主题场景；有效主题识别的正向测试仅在隔离临时目录完成，没有为测试擅自应用主题。
- 其它 ROM 布局、全部作用域、浅色模式和同进程实时卸载主题未全面覆盖。
- 已运行目标进程可能仍持有旧 dex/已改过的视图，需重开目标应用；没有重启 SystemUI，所以不能声称当前 SystemUI 已加载此版本。
- 读不到有效主题资源时保守不注入，不能将这种未知状态当成用户确认默认主题。后续若其它 ROM 路径不同，需依据实机证据适配。
- A→B 主题切换时缓存归属/原子发布仍属于独立待办；本轮修复无主题仍被旧缓存激活的问题，不宣称完成缓存全部治理。

# 必须永远记忆住的内容

> 每次修改代码、构建、发版之前，先把这八条读一遍。任何一条不满足就别动手。

## 0. 动手前的固定动作（缺一不可）

1. **改前查文档**：服务器 `/本地盘/project/MCTGA/文档` 下四份都要读（本文件、作者的要求、需要避开的坑、更新总集）。
2. **改前查源码**：先搜有没有相同实现，别重复造轮子。
3. **改后写更新总集**：**每一次改动都要在 `更新总集.md` 里追加一行**，写清楚三件事——
   - 改了什么（功能/文件/行为）
   - 为什么改（问题、需求、来源）
   - 影响面（哪些界面/包/用户场景会变）
   只递增 versionCode 也要写，不能只改代码不记账。
4. **改后记坑**：本次踩到的、或者新发现的注意点，写进 `需要避开的坑.md`（现象 → 原因 → 做法）。哪怕只是“某个文案是拼接的、要整句改”这种小坑也要记。
5. **改后递增版本号**：`module/AndroidManifest.xml` 的 `versionCode` +1、`versionName` 递增（`0.4-betaN`）。
6. **改后同步**：APK / 源码包 / 文案表 / 文档上传到服务器对应目录。

## 1. 通用性

以 ColorOS 11 ~ 17、realme UI 2.0 ~ 7.0 全都能用为前提。不要针对某一台机器、某一个版本写死。

## 2. 素材必须来自主题文件

- 插画、背景、各界面素材一律从主题包里读，**模块本身不得内置任何主题素材**（APK 里只有应用图标）。
- 主题作者要能按规范自定义**各个适配界面**用的素材，换一张图就是一个新角色的主题。

## 3. 先想方案再写码

写之前先确认：有没有更好的做法、会不会影响后续、会不会让已有功能不可用。不写屎山。

## 4. 不重复造轮子

动手前先搜源码里有没有相同实现，一个功能只保留一种实现方式。

## 5. 不八股、不废话、不瞎搞

优先稳定；**不动任何可能导致系统无法开机的分区**（`/data/theme` 写入按红线流程走）。

## 6. 功能门槛

- **主题锁定**：以“只有 Shizuku、没有 Root”为前提设计，有 Root 也要能用。
- **深色模式**：只有同时具备 Root 权限和 LSPosed 权限才允许使用；不满足时用户**看不到**这个功能。

## 7. 测试顺序

先在亮色（或深色）下把一系列界面测完，再切到另一套；不要频繁重启 SystemUI。

## 8. 态度

不催作者、不添乱、不倒卖。吃白饭惹作者生气的事不要做。

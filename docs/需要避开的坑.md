# 需要避开的坑

> 全是实测踩出来的，按“现象 → 原因 → 做法”记。

## 环境 / 通道

- **`exec("su")` 报 ENOENT**：Sui（Zygisk）接管后不往文件系统放 su，app 的挂载命名空间里没有 `/system/bin/su`。别用“su 文件是否存在”判断 Root，要判断 binder 通道（Shizuku/Sui）或实际执行结果。
- **Sui 与 Shizuku 身份不同**：Sui 是 uid 2000 / `u:r:ksu:s0`，读不到 `Android/data`；Shizuku（无线调试）是 uid 2000 / `u:r:shell:s0`，能读写。锁定/解锁必须用能写 `Android/data` 的身份。
- **ColorOS 双身份挂起**：同一个包可能被 root 和 shell 各挂起一次，只解一边会一直显示“已挂起”。解冻按 `suspendingPackage` 记录选身份。
- **`pm install` 读不了 `/storage`**：先 `cp` 到 `/data/local/tmp` 再 `pm install -r`。

## 构建

- `javac` 必须 `--release 8`（android.jar 的 LambdaMetafactory 不全），desugar 交给 d8。
- `jar uf` 追加文件会重写 zip，`resources.arsc` 偏移不再 4 字节对齐 → Android 11+ 装不上；要用 `tools/Align` 重新对齐。
- 多个 `-C` 才能追加多个目录里的文件（`-C dir a b` 里 b 会被当成相对当前目录）。

## 运行时

- 更新 APK 后目标应用要重启才加载新 dex。
- `/storage` 上 `mv`、`sed -i` 可能把文件截成 0 字节；大文件先在 `/data/local/tmp` 改再写回。
- 主题商店有缓存：换主题后详情页可能还是旧主题，先 `force-stop` 商店再打开。
- `dumpsys package | grep suspended=` 在 Sui shell 下不可靠，用 `PackageManager.isPackageSuspended()`。
- 每改一次亮/深色就重启一次 SystemUI 会让人崩溃——按规则 7 测试。

## 主题与开屏风险

- **写 `/data/theme` 可能导致无法开机**：只取 `.theme` 里的 `com.*` 成员、逐个 `unzip -t`、先备份、`.tmp` 原子替换，并且必须先得到作者明确同意。
- `Themes` 是目录不是文件：锁定时 `mv` 成 `.Themes.lockdir-<时间戳>`，解锁再还原；不要直接 `: > Themes`。
- 主题包内的图是 9-patch，替换必须保留 1px 边框，且要用 PNG（JPEG 会糊掉边框）。

## 框架

- 不碰 LSPosed 守护进程：`lspctl stop`、`kill lspd`、改 `modules_config.db` 后重启 lspd 都会让框架整体失效。
- 改作用域只让作者在 LSPosed Manager 里勾；模块只负责把包列进 `xposed_scope` 推荐数组。
- `handleLoadPackage` 开头有 `TARGETS` 白名单，新包只加进作用域、不加进名单，日志里只会打一行 `MCTGA loaded` 就返回（本次踩过）。
- 资源层 hook 用 `hookAllMethods`：Android 17 上没有 `Resources#loadDrawable(TypedValue,int,Theme)` 这个精确签名。
- 文案外置（`Texts`）要读 `/storage/emulated/0/MCTGA/texts.json`，必须声明 `MANAGE_EXTERNAL_STORAGE` 并在系统里开启“所有文件访问”，否则读取静默失败（表现为改文案没反应）。

## 文案外置（Texts）相关

- **默认表是“源码字面量”抓出来的**：里面混着拼接片段（`" · 商店已挂起"`）和已废弃字符串（`"1  选 .theme → …"`）。片段命中不了整句，废弃项改了也没效果。改文案优先用**整句键**，带数字的用 `%n` 模板。
- **多行文案的换行**：默认表里存的是字面 `\n`，界面文本是真换行。`Texts.load()` 会把键值里的字面 `\n` 转成真换行再比较，否则永远匹配不上。
- **不要做全局空行折叠**：beta46 试过“折叠连续空行/去首尾空行”，会误伤正常多行文案，已撤回（beta47）。清空某一行留下的空行目前不处理。
- **界面会被周期性重绘**：应用自己 `setText` 改回原文后，只在文件变化时应用会漏掉。必须每 800ms 无条件重跑一次 `Texts.apply()`。
- **文件读不到要检查权限**：读 `/storage/emulated/0/MCTGA/texts.json` 需要 `MANAGE_EXTERNAL_STORAGE`，且必须在 manifest 里声明（只 `appops set` 不声明无效）。
- **改文案后的验证方式**：`read_image` 偶发报 `No value for path` 打不开截图，改用 `uiautomator dump` + grep 文本，或直接看 `texts.json` 与界面节点的差异。
- **片段替换门槛**：≥3 个字符且含文字/数字才允许片段替换（纯符号会被跳过，避免 `（` `）` 被全局替换）。

## 云控（Cloud）

- 轻档只读一个 `cloud.json`：`minVersionCode` / `blockedVersionCodes` / `notice` / `downloadUrl`，**只提示不锁功能**，失败（超时、断网、返回值不是 200）一律静默。
- 现在 `Cloud.URL` 是空串，等于未启用；启用要填公网地址（IPv6 用 `http://[2400:...]:5244/...` 的方括号写法）。
- 如果走 OpenList 的 WebDAV，请求要带 `Authorization: Basic ...`，`HttpURLConnection` 不会自动处理 URL 里的 `user:pass@`，得手动设请求头；更省事的做法是给 `cloud.json` 开一个免登录的分享直链。
- HTTP 明文只适合局域网；公网请上 HTTPS，否则公告和更新地址会被中间人改。

## 云控部署（服务器侧，2026-11 实测）

- 服务器 `zakoserver`（Ubuntu，x86_64）：nginx 由宝塔安装，配置目录 `/www/server/panel/vhost/nginx/`（`nginx.conf` 第 96 行 include 该目录）。
- 云控目录：`/www/wwwroot/mctga-cloud/cloud.json`，nginx 独立 server 监听 `8081`（`mctga-cloud.conf`），`nginx -t` 通过后 `-s reload`。
- 防火墙：`ufw allow 8081/tcp` + `iptables/ip6tables -I INPUT -p tcp --dport 8081 -j ACCEPT`（服务端 INPUT 默认 DROP）。
- 域名 `mc.nyafish.top` 只有 **AAAA 记录**（IPv6），ddns-go 会更新；IPv4-only 网络访问不到，别用它做唯一入口。
- **Android 9+ 默认禁止明文 HTTP**：`Cloud.URL` 用 `http://` 时必须在 manifest 开 `android:usesCleartextTraffic="true"`，否则请求静默失败（公告永远不显示）。长期方案是给该域名配证书走 HTTPS。
- App 需要 `android.permission.INTERNET`，本模块原先没有，是这轮补上的。

## 云控写入（PUT）

- nginx 8081 用 `dav_methods PUT` 提供写入，`limit_except GET` 才要 Basic 认证（读保持公开）。
- **目录属主必须是 www**：`/www/wwwroot/mctga-cloud` 归 root 时 PUT 会返回 500；`chown -R www:www` 后正常（204）。
- `.htpasswd` 用 `openssl passwd -apr1 <密码>` 生成，账号 `mctga`。
- App「MCTGA 云控」内置了 Basic 凭据（`mctga:MeiYou520`），换密码要同时改 nginx 的 .htpasswd 和 App 里的 `AUTH`。

## 云控 × Hook / 深色解锁

- Hook 在目标应用进程里拿不到 Context，读云控状态改用系统属性：App 用 `setprop persist.mctga.cloud_block 0/1` 写，Hook 用 `OsVersion.prop("persist.mctga.cloud_block")` 读，为 `1` 时直接 `return`（不注入）。写属性需要 Root 通道。
- 深色解锁状态存在 `SharedPreferences("cfg")` 的 `dark_unlocked`；**手工往 `/data/data/<pkg>/shared_prefs/cfg.xml` 里塞值不可靠**（SELinux 上下文是 `system_data_file`，进程读不到），要验证持久化只能在界面里真解锁一次。
- 深色开关（开/关）不再要密码，密码只保留在“连点版本号 7 次”这个入口；`onBackPressed` 在云控停用时被拦，只能点「退出应用」。

## SystemUI 重启开关

- 切深/浅色时的 SystemUI 重启由 `persist.mctga.systemui_restart` 控制：`1` = 重启（配置立刻生效但会黑屏一下、回锁屏），`0`/未设 = 不重启，只清背景缓存（`sBg`/`sBgKey`），背景要等窗口重建才刷新。
- 默认必须是 `0`：作者反馈切换深浅色时黑屏跳锁屏体验不可接受。
- 深色适配关闭（`mctga_dark_attach=0`）时 Hook 根本不挂，也就不存在重启；如果关了还重启，先确认那个 SystemUI 进程是不是关之前就启动的旧进程。

## 构建产物与源码包的对应关系

- 发布包和源码包**必须是同一次构建**：先 `sh build.sh`（会自动写 `BUILD.txt`），再 `tar czf` 打包源码（排除 `out/`、`.git` 与 `BUILD.txt` 同目录打包）。
- 别人用同一份源码重建，`classes.dex` 大小可能不同（javac / d8 / android.jar 版本差异），**不能用 dex 大小判断是否同源**；要比对 `SHA256SUMS` 里 `.java` 的哈希，或看 `BUILD.txt` 的工具链记录。
- 本机发布环境：`javac 17.0.20`、`d8.jar md5 db3fc3ba1d6f929f0e455e13f85cd09f`、`android.jar md5 3d3a962caad5b8ee4560183126b10afa`。（历史记录：beta65 及以前那条线是在 PC 上用 JDK 17 构建的。）
- **Java 版本不统一 → dex 对不上（beta67 解决）**：现象是同一份源码在本机（javac 21.0.13）和 PC（17.0.20）编出的 `classes.dex` 差约 1KB，谁也说不清发布包是不是这份源码编的；原因是 javac 大版本之间字节码与常量池生成策略不同，`--release 8` 只统一语言级别、不统一编译器实现。做法：基线写进 `tools/toolchain.env`（`PIN_JAVA_VERSION` 等），`build.sh` 校验失败就 `exit 1`；换 JDK 必须先改基线并同步文档，不要用环境变量偷偷绕过（`ALLOW_JAVA_MISMATCH=1` 只给本地试验）。
- **`--release 8` 在 JDK 21 上仍可用**，但会提示 source/target 8 已废弃，属正常，别为此升级语言级别（android.jar 的 `LambdaMetafactory` 不全，lambda 编不过）。

## 深色适配冒烟测试（0.5 发布前，可复用）

- 脚本 `/data/local/tmp/darktest.sh`：`pm list packages` 判断是否安装 → `cmd package resolve-activity --brief` 拿真实入口 → `force-stop` → `am start` → 等 5s → `screencap` → `Img band` 量背景亮度 → 用模块日志行数 diff 统计该包的 `fail/Exception`。19 个包约 2 分钟，结果写 `/data/local/tmp/darktest/report.txt`。
- **模块日志不在 logcat**：`XposedBridge.log()` 写 `/data/adb/lspd/log/modules_*.log`，必须按包名 `grep -a '(pkg'` 才能分应用；`logcat` 里只有 `MCTGA loaded` 那类 `android.util.Log`。
- **`com.android.contacts` 的启动意图会落到 `ResolverActivity`**：系统弹“用哪个应用打开”，`topResumedActivity` 不是 contacts，但模块已经注入（日志里有 `hooked inner` / `dialpad hooked`）。别用前台判定它失败。
- **首帧可能是白色加载页**：`com.coloros.shortcuts` 第一次量到 183.9，重开稳定在 48.7。必须等够 5 秒，或连拍两张取后一张。
- **3 个包没有 LAUNCHER 入口**（`com.oplus.wirelesssettings`、`com.oplus.linker`、`com.coloros.video`），只能跳过，不算失败。
- 亮度基线（中间横带 0.30–0.60）：<40 偏黑（家人守护 20.4、小布 35.3 属于插画本身很暗），50–75 正常，>100 基本等于没压暗（云服务 105.6、使用技巧 105.6 是它们背景本来就很浅）。

## 深色背景亮度（0.5.1 起模块不再压暗）

- **模块对深色背景不做任何处理**：`withMask()` 夜间直接 `return base`，背景就是主题 `drawable-night-xxhdpi` 那张图的原始亮度。`MASK_NIGHT_TINT`、`persist.mctga.bg_tint`、`nightTint()` 已在 0.5.1 删除，**别再加回来**——深色底归主题作者，模块再压一层就是跟作者的图打架。
- 浅色仍叠 60% 白蒙层（`MASK_DAY`，是提亮不是压暗）；`alreadyMasked()` 现在只认 `MASK_DAY`，防重复叠层。
- **界面仍然偏暗怎么判断**：先量背景带亮度，>60 说明模块没压暗，偏暗来自主题的 night 图本身或应用自己的遮罩（scrim）→ 找作者调图，不是改模块。
- **量亮度的方法**：`Img avg x.png` / `Img band x.png 0.30 0.60`（工具在 `/data/local/tmp/imgtool`），取中间横带避开状态栏和底部栏；`read_image` 偶发报 `No value for path`，数值比对更稳。
- **截图前先确认前台**：`am start -n <错 activity>` 会静默失败，`screencap` 抓到的是上一个应用；用 `cmd package resolve-activity --brief <pkg>` 取真实入口，再 `dumpsys activity activities | grep topResumedActivity` 确认。`com.coloros.filemanager` 的入口是 `com.oplus.filemanager.main.ui.MainActivity`。
- 历史基线（同一台机、文件管理）：0.4 线压暗 39.4 → 放宽到 0xFFB4AAC8 后 61.5 → **0.5.1 原色 82.9**。

## LSPosed 检测误判（beta70）

- **现象**：LSPosed 明明在跑，App 的深色卡片却提示「没有 lsposed 和 root，无法使用」。实测设备上 `pidof lspd` = 3511、`/data/adb/lspd` 存在。
- **原因一：探测通道选错**。`refreshHook()` 直接按 `ShizukuBridge.granted()` 决定用哪个身份，有 Root 时也走 Shizuku shell（uid 2000 / `u:r:ksu:s0`），而它**看不到 `/data/adb`、也拿不到 `pidof lspd`**。同一命令实测：root 返回 `3511` + `LSPD_DIR`；`su 2000 -c '...'` 返回空、rc=1。
- **原因二：结论被 latch 住**。`hookChecked=true` 之后不再重测，而首次探测常常跑在 `refreshRoot()` 完成之前（那时 `rootReady` 还是 false，只能用 shell 身份），Root 就绪后也不会纠正。
- **做法**：探测改用 `useShizukuChannel()`（Root 优先）；空输出只在「走 shell 身份」或「命令本身失败」时算“无法确认”，Root 通道下为空才算“真的没运行”；`refreshRoot()` 完成后，若上一次是 shell 身份得出的结论就清 latch 重测。文案按三种原因分开写，别一律说“没有 root”。
- **别只信 `pidof`**：部分 ROM 上 `pidof` 受限，`ls -d /data/adb/lspd` 更可靠，两个都试、任一命中即可。

## 清理死代码 / 合并重复实现（beta69）

- **怎么确认一个方法没人调用**：没有 IDE，就用 `cat *.java | grep -o "方法名" | wc -l`，全工程只出现 1 次（就是定义那行）才算孤儿。**但要排除框架入口**：`initZygote`、`handleLoadPackage`、`onCreate/onResume`、`onBinderDead`、`onRequestPermissionResult` 这些由 Xposed / 系统回调，计数也是 1，删了就整个模块失效。
- **同名重载会骗过计数**：`packBaseDir(pkg, activity)` 只有一句 `return packBaseDir(pkg);`，按名字计数看不见“孤儿”，得看方法体是不是纯转发。清理时优先找这种空壳重载。
- **死字段比死方法更隐蔽**：字段只写不读（`sPending`、`sLastDeep`、`sDecorRef`、`unlockPrompted`）编译器不报错，要按“全工程出现次数 ≤ 2（声明 + 赋值）”筛。
- **`Texts.changed()` 留着会误导**：beta44 已经把文案改成每 800ms 无条件重贴，这个“文件是否变化”的接口没人再调，留着下次改动容易照着它又写回轮询。同类情况：`mtime` 字段仍被 `load()` 用着，不能一起删。
- **minSdk 曾经有三处**：manifest `uses-sdk`、`build.sh --min-sdk-version`、d8 `--min-api`，三处不一致会做出“装得上但判定按另一套”的包（本次发现 manifest 29 / `OsVersion.MIN_SDK` 30）。现在只保留 manifest 一处，`build.sh` 从 manifest 读出 `MIN_SDK` 再传给 d8，aapt2 不再传 SDK 参数（省略时以 manifest 为准）。
- 删完必须 `sh build.sh` + 装机跑一遍界面：本次 `classes.dex` 从 1136320 掉到 1134216（-2104 字节），`Hook.java` 1390 → 1290 行。

## 构建提速（beta68 实测）

- 现象：全量构建 14s，其中 d8 约 6.3s、javac 2.4–4.0s。原因不是代码量，而是 javac/d8/apksigner 都是**跑几秒就退出的短命 JVM**，默认分层编译还没热身进程就结束了。做法：javac 加 `-J-XX:TieredStopAtLevel=1 -J-XX:+UseSerialGC`，d8/apksigner 直接加 `-XX:...`；同机实测 d8 6.3s→3.2s。**反例**：`-XX:ArchiveClassesAtExit`（AppCDS）在 Termux JDK 上直接报 `unsupported when base CDS archive is not loaded`，别指望它。
- **依赖 dex 缓存**：6 个依赖 jar 内容固定，dex 一次就存 `out/.cache/deps-<md5>.jar`，之后每次只编本工程的类再合并。缓存键 = `cat 6个jar | md5sum`，依赖一换自动失效，旧缓存自动清；`out/.cache` 不进源码包、不进 `SHA256SUMS`。
- **合并 dex 与直编 dex 字节不同，但类集一致**：合并后 `classes.dex` 同为 1136320 字节，`Lxwdy/deepseek/test/` 引用 135 处、`Lorg/apache/commons/compress/` 622 处，与直编完全一样。所以**别拿 sha256 比对判断有没有漏类**，比大小 + 类引用计数 + 装机跑一遍。
- `jar uf` 支持一条命令带多个 `-C`（`jar uf a.apk -C dir1 f1 -C dir2 f2`），两次改一次能省一次 JVM 启动。
- **JDK 25 试过，暂不采用**：Termux 仓库有 `openjdk-25`（25.0.5，未重写前缀，靠 `LD_LIBRARY_PATH` 指到解包目录的 `usr/lib` 就能跑），但同机实测 javac25 与 javac21 耗时相当（2.3–2.6s vs 2.2–2.6s），且 javac25 编出的 56 个 `.class` 与 21 不同，会让 dex 基线整体漂移；d8 跑在 25 上只快 0.3s，却要多带 259MB 未打补丁的树。要换就整包换并重设 `PIN_JAVA_VERSION`。
- **`SHA256SUMS` 会过期**：现象是 `sha256sum -c` 报 `No such file`；原因是清单是手抓的，删文件（如 `module/assets/bg_day.png`、`bg_night.png` 这类主题素材）后没重生成，里面还留着空文件 `SHA256SUMS.new`。做法：按固定清单重生成（`LICENSE`、`README.md`、四个 `build*.sh`、`cloud.json`、`texts*.json`、`BUILD.txt`、`交接文档.md`、`module/ docs/ tools/ texts-editor/ cloud-editor/` 全部文件），清单里不能出现主题素材。
- **签名密钥不进源码包（0.5.1 起）**：`tools/eta.keystore` 只留在本机用于签名，源码包与 `SHA256SUMS` 都不再包含它；`tools/` 目录照常发布（`Align.java`、`XposedBridgeAPI-82.jar`、`icon/`、`toolchain.env`、`toolchain.md`）。历史教训：0.4 以前公开仓库里直接躺着 `tools/eta.keystore`，任何人都能签同证书的包覆盖安装，发现后已从仓库删除并改写清单。生成清单时用 `find ... | grep -v tools/eta.keystore` 过滤。
